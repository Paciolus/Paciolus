# =============================================================================
# PINNING RULE (Sprint 777, 2026-10-19) — read before changing any pin
# =============================================================================
# Two pin styles are used deliberately. Pick the right one for a new dep.
#
#   ==  EXACT PIN — the framework/runtime surface, where an unreviewed
#       upstream change is more dangerous than a late CVE patch: web
#       framework, data layer, migrations, money, document generation,
#       scheduler, APM. Reproducible builds; a human reviews every bump.
#
#   >=  FLOOR — leaf libraries consumed through a narrow, stable API, and
#       the security block at the bottom of this file, where CVE currency
#       matters more than byte-for-byte reproducibility. Every fresh
#       `pip install -r requirements.txt` (CI and the production Docker
#       build) resolves these to latest, so they self-heal.
#
# THE TRADEOFF, AND WHY IT BIT US (2026-10-19):
# Exact pins do not self-heal. They rot silently — a CVE published against
# the pinned version just sits there. When the repo went dormant from
# 2026-05-01 to 2026-10-19, `pip-audit` flagged exactly two packages:
# PyJWT and python-multipart. Those were the ONLY two CVE-carrying
# dependencies pinned with `==`. Every floor-pinned package self-healed on
# each fresh resolve. Two red blocking CI gates, and the entire 13-PR
# backlog sat at mergeStateStatus=BLOCKED behind them.
#
# THEREFORE: exact pins are only safe while the weekly
# `.github/workflows/dependency-compliance.yml` pip-audit is ENABLED and
# GREEN. That job is the sole mechanism that can catch rot in the `==` half
# of this file. It had been failing for months and was then auto-disabled by
# GitHub after 60 days of repo inactivity, which is precisely how the rot
# went unnoticed. If that job is ever red or disabled, this file is
# unmaintained regardless of what the pins say.
#
# NOT DONE DELIBERATELY: `starlette` carries no constraint here even though
# it is the HTTP core beneath FastAPI. `fastapi`'s own range governs it, and
# adding a second constraint would risk resolution conflicts on every
# FastAPI bump for no reproducibility gain (fastapi is exact-pinned, so its
# allowed starlette range is already fixed).
# =============================================================================
